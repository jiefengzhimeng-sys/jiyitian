# 「记一天」前后端联调报告

- 联调时间：2026-11-02
- 联调方式：本地不接云环境，用「真页面代码 + 真云函数 + 内存数据库」跑通全链路
- 结论：**三套测试 97 项全绿**（后端 55 / 前后端联调 32 / Mock 冒烟 10），修掉 9 个真实缺陷

---

## 一、联调方式：为什么不是「打开开发者工具点一遍」

微信开发者工具里点一遍能发现的问题，永远是**当场能看见的**问题。字段少一个、翻页丢几条、临时链接过期——
这些都要等真实用户踩到才暴露。

所以这次搭了一个极简小程序运行时 `scripts/integration/mini-runtime.js`（约 300 行），把微信客户端这一层假掉：

```
真实页面 .js  →  services/cloud-repository  →  wx.cloud.callFunction
             →  api.main  →  routes  →  service  →  dao  →  内存数据库
```

- `wx` 全部 API 打桩：Storage、Toast、Modal、路由、`chooseMedia`、`RecorderManager`、
  `cloud.uploadFile`、`cloud.getTempFileURL`、隐私授权
- `Page / App / getApp / getCurrentPages / setData`（含 `a.b` 路径）按小程序语义实现
- `wx.cloud.callFunction` 直接调到云函数 `main()`，请求日志、返回码全部可断言
- 数据库换成 `memory-cloud.js`，并**刻意复刻云开发的三个坑**：`add` 主键冲突抛错、
  `update` 不存在的文档抛错、`doc().get()` 不存在抛错

于是页面里的 `this.setData`、`feedback.fail`、`onShow` 刷新标记，全是真代码在跑。
页面用错字段、接口少了返回、前后端口径不一致，测试直接红。

三套测试的分工：

| 命令 | 覆盖面 | 数量 |
|---|---|---|
| `(cd cloudfunctions/api && node scripts/local-test.js)` | 后端 action 层：校验、越权、幂等、配额、降级、对账 | 55 |
| `node scripts/integration/e2e.js` | 页面 → 云函数全链路 | 32 |
| `node scripts/integration/mock-smoke.js` | `USE_MOCK=true` 的另一条链路 | 10 |

## 二、修掉的 9 个缺陷

### 1. 前端拿不到 openid（阻断级）

`user.init` 只返回了 profile，没有 `openid`。`app.js` 里 `res.result.data.openid` 恒为空，
兜底成 `'local'`，云存储路径变成 `records/local/20261102/xxx.jpg`。

**修**：`routes/index.js` 的 `user.init` 在返回里补 `openid`（只在这一个接口返回，其余接口一律不带，
避免 openid 散落到页面数据里）。

### 2. 缩略图把 2 小时过期的临时链接写进了数据库（阻断级）

`record.js` 提交前把 thumb 的 fileID 换成 `getTempFileURL` 的 https 链接再落库。
记录是长期数据，2 小时后列表缩略图整片裂图；而且后端 `domain/record.js` 的注释早就写明
「不接受 http 临时链接」。

**修**：落库只存 `cloud://` fileID（`image` 组件可直连渲染）；只有详情预览、语音播放
这类必须 https 的场景，才在**读取时**换链接。

### 3. 草稿恢复覆盖入口参数（体验级，但很扎眼）

`onLoad` 先处理 query 再 `restoreDraft()`，草稿里的 `category` / `tab` 把入口参数盖掉：
首页点「拍照 → 饮食」进去，看到的是上次「文字 → 运动」的草稿；点「体重」快捷入口，
体重面板也不会展开。

**修**：`restoreDraft()` 先行，`applyEntry(query)` 后再覆盖——入口是用户当下的选择，优先级更高。

### 4. 补记更早日期不重算 streak（数据正确性）

原来只在「今天 / 昨天」有新记录时重算 streak。补记前天时，今天+昨天+前天本应连成 3 天，
但首页和打卡页一直显示 2，直到用户下次记今天的东西才被修正。

**修**：只要落库日期落在 streak 观察窗口（120 天）内就重算。代价是点查 ≤120 条 `daily_aggs`。

### 5. 游标分页丢记录（最隐蔽的一个）

`record.list` 的游标是 `(recordDate, createdAt)`，条件是 `createdAt < cursor`。
同一毫秒写入的多条记录 `createdAt` 相同，翻页时这些「兄弟记录」被条件整批排除：
**16 条记录翻三页只翻出 13 条，静默丢 3 条**。线上表现是「昨天明明记过，时间线里没有」。

**修**：
- 服务端 `core/ids.nextTimestamp()` 生成实例内单调递增的 `createdAt`，撞点消失
- 前端 `timeline.mergeGroups` 按 `_id` 去重兜底（宁可重复一条，不能丢）
- 后端单测加了一条守卫断言：翻到底必须正好 16 条

### 6. 总结页在云端首次进入是空白封面（体验级）

云端 `summary.get` 没生成时返回 `null`（定时任务是周期末预生成，用户可能提前进来），
而页面只在「记录不足」时有空态，`null` 会渲染成一个没有标题、没有正文的空封面。

**修**：页面补 `empty` 空态（文案 + 「生成总结」按钮）；同时把 Mock 仓储改成
「没生成就是 null」，两边行为对齐（原来 Mock 会自动用模板造一份，导致演示和真机不一样）。

### 7. 前后端周期口径不一致（数据正确性）

后端 `periodRange('week')` 用**本周一至周日**、`month` 用**自然月**；
总结页却用「近 7 天 / 近 30 天」算统计。跨周跨月时，总结正文说的周期和曲线画的区间不是同一段。

**修**：前端 `utils/date.js` 补一套与后端同口径的 `periodRange`（含 ISO 周编号），
总结页改用它；e2e 里加了一条「前后端 periodRange 必须一致」的对账断言。

### 8. 提醒设置把 `undefined` 写进数据库（功能静默失效）

`updateProfile` 无论改什么字段都会调 `remindersDao.save()`，只改昵称时会把
`remindOn: undefined` 写进去，`listDue` 的 `remindOn: true` 条件从此永远扫不到这个用户。

**修**：`reminders.save` 过滤 `undefined`；`statsService.updateProfile` 只在真改了提醒字段时才写提醒表。

### 9. 契约漂移：徽章规则两套实现

Mock 的打卡徽章是 `d7 / night / water / d21` 四条，云端是 `d3 / d7 / d21 / d60 / first / rich` 六条，
演示时徽章墙和真机不是一个样子。

**修**：Mock 徽章规则与云端 `dao/userStats.BADGES` 对齐；`getProfile` 补上云端有的 `streak` / `longest`。

## 三、联调覆盖到的流程

| 链路 | 覆盖内容 |
|---|---|
| 冷启动 | `user.init` 建档、openid 回填、空库首页不报错 |
| 记录写入 | 文字 / 图片（2 张，4 次 uploadFile）/ 语音（4.2s）/ 只有体重，四条路径全走真实上传 |
| 幂等 | 同内容 5 分钟内重复提交不产生第二条 |
| 补记 | 前天 / 昨天可补，超过 7 天被拒 |
| 首页 | 今日流、近 7 天柱条、情绪卡、连续天数 |
| 时间线 | 游标分页翻到底一条不漏、跨页去重、分组不重复、组内时间倒序 |
| 详情 | 字段映射、thumb/origin 分别换临时链接、越权按「不存在」、软删后列表消失 |
| 数据页 | 体重曲线（含涨跌趋势）、情绪环形图（百分比归一到 100）、饮食柱状、90 天区间、180 天上限 |
| 打卡 | 连续天数、月历点阵、徽章解锁数 |
| 我的 / 设置 | 档案字段（照片数 / 语音数）、开关乐观更新与持久化、提醒时间 |
| AI 总结 | 未生成态 → 生成（三段块 + 标签 + 免责声明）→ 缓存命中不重复烧 token → 日/周/月三种 |
| 校验 | 空内容、体重越界、未来日期、非法 type、未知 action、内部动作鉴权 |

## 四、遗留问题（不影响联调，但上线前要处理）

1. **真机验证还没做**：本地链路覆盖了逻辑，但真机的选图压缩、录音权限、`previewImage` 手势、
   自定义 tabBar 选中态，必须用真机再过一遍。
2. **云环境还没接**：需要真实 AppID + 云环境 ID，控制台建 9 个集合与索引，`USE_MOCK=false`。
3. **订阅消息未接**：`reminders` 表结构已就绪，缺模板 ID 与 `requestSubscribeMessage`。
4. **`security.mediaCheckAsync` 未接**：媒体资产目前直接写 `passed`，上线前要接内容安全。
5. **`timerDaily` 单次限 500 用户**，用户量上来要分片。
6. **同一毫秒跨实例写入**仍可能撞点（概率极低），升级路径见 README 第六节第 6 条。

## 五、怎么复现这份报告

```bash
cd jiyitian

# 后端 55 项
(cd cloudfunctions/api && node scripts/local-test.js)

# 前后端联调 32 项
node scripts/integration/e2e.js

# Mock 链路 10 项
node scripts/integration/mock-smoke.js
```

联调脚本本身也是可改的资产：新增页面流程时，照着 `e2e.js` 里 `xxxFlow()` 的写法加一段
`createPage(路径)` + 触发生命周期 + 断言 `page.data` 即可，不需要云环境。
